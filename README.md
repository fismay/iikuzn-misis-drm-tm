# Рекомендации для личного кабинета

Прототип подбирает до трёх товаров для клиентов B2B и B2C по истории покупок. Для каждой рекомендации показывается её источник; связи между ранее купленными и предложенными товарами доступны на схеме. Если связей недостаточно, выдача дополняется популярными товарами.

## Что умеет проект

- Подготавливать данные о клиентах, товарах и покупках в едином формате.
- Строить рекомендации по связям товаров и популярности, исключая уже купленные товары.
- Рассчитывать Precision@3, Fill Rate и другие показатели на истории.
- Показывать рекомендации, объяснения и результаты проверки в интерфейсе Streamlit.

## Установка и запуск

Требуется Python 3.11 или новее. Команды для macOS и Linux:

```bash
git clone https://github.com/fismay/iikuzn-misis-drm-tm.git
cd iikuzn-misis-drm-tm
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install -e .
python -m pytest tests -q
python -m app.run_pipeline --synthetic --output artifacts/demo
python -m streamlit run app/streamlit_app.py -- --artifact-dir artifacts/demo
```

Для Windows PowerShell команда активации: `.venv\Scripts\Activate.ps1`. После запуска Streamlit откройте адрес, который появится в терминале.

Демонстрация использует **синтетические данные**: её метрики показывают работу кода и не являются результатами на клиентах. Результаты сохраняются в `artifacts/demo/`.

## Данные и проверка

Загрузчик принимает отдельные CSV- или XLSX-файлы клиентов, товаров и транзакций с явным JSON-сопоставлением полей. Подробности — в [описании сопоставления](docs/data/input_mapping.md). Реальные выгрузки, локальные сопоставления и результаты с идентификаторами клиентов не следует добавлять в репозиторий.

Книга организаторов содержит несколько листов и требует отдельной подготовки: штатный загрузчик не читает её напрямую. Также встроенный бэктест использует собственный временной протокол и отличается от протокола организаторов. При сравнении результатов необходимо явно указать выборку, период и определения метрик. В частности, Fill Rate в протоколе организаторов — доля клиентов с хотя бы одной рекомендацией, а не доля заполненных позиций в списке.

Данные о ценах и показах отсутствуют, поэтому по ним нельзя измерить прирост выручки или доказать влияние рекомендаций на продажи. Проверка на истории не заменяет эксперимент в личном кабинете.

## Структура

- `src/reco_mvp/data/` — подготовка и проверка данных.
- `src/reco_mvp/recommender/` — модель рекомендаций.
- `src/reco_mvp/evaluation/` — проверка на истории и метрики.
- `app/` — запуск сценария и интерфейс.
- `contracts/` — формат данных и программные интерфейсы.
- `docs/` — описание модели, протокола и запуска.
- `tests/` — автоматические проверки.

Подробнее: [описание алгоритма](docs/model/algorithm.md), [протокол оценки](docs/evaluation/protocol.md) и [инструкция по сборке](docs/integration/ASSEMBLY.md).
