# Рекомендации для личного кабинета

Прототип подбирает до трёх товаров для клиентов B2B и B2C по истории покупок. Для каждой рекомендации показывается её источник; связи между ранее купленными и предложенными товарами доступны на схеме. Если связей недостаточно, выдача дополняется популярными товарами.

## Что умеет проект

- Подготавливать данные о клиентах, товарах и покупках в едином формате.
- Строить рекомендации по связям товаров, популярности и продлению внутри семейств (`product_group`), исключая уже купленные товары.
- Точная реализация официального протокола проверки организаторов с воспроизведением их baseline-таблицы (golden-тесты).
- Обучаемый ранжировщик (LTR) поверх эвристики — точность повышена в ~2.5 раза относительно лучшего baseline организаторов (см. таблицу ниже).
- Рассчитывать Precision@3, Fill Rate и другие показатели на истории.
- Показывать рекомендации, объяснения и результаты проверки в интерфейсе Streamlit.

## Результаты на официальном периоде организаторов

Единственная проверка на официальном тестовом периоде (с 07.09.2026); модель и гиперпараметры зафиксированы до неё, подбор — только на более ранних внутренних окнах (методика — [docs/model/learned_ranker.md](docs/model/learned_ranker.md)). Baseline'ы организаторов воспроизведены скорером точно (golden-тест).

| Метод | Группа A: все / B2B / B2C | Группа B: все / B2B / B2C | Fill Rate A | Доля вариантов (A) |
|---|---|---|---|---|
| baseline «Популярность» | 5.44 / 3.75 / 20.0% | 7.36 / 5.22 / 20.0% | 100% | 0% |
| baseline «Совместные покупки» | 5.64 / 4.53 / 15.24% | 6.01 / 4.54 / 14.67% | 92.3% | 10.5% |
| Эвристика проекта | 12.76 / 11.81 / 20.95% | 13.76 / 12.70 / 20.0% | 100% | 35.7% |
| + Обучаемый ранжировщик | **14.34 / 13.58 / 20.95%** | **15.50 / 14.51 / 21.33%** | **100%** | 35.9% |

Группы A (337) и B (172) — по протоколу организаторов; размеры совпали точно. B2C в проверке мал (35/25 клиентов) — результат шумный. Это наблюдение на истории, а не измеренный рост выручки: цен и показов в данных нет. Подробности и ограничения — [docs/evaluation/organizers_protocol.md](docs/evaluation/organizers_protocol.md).

## Установка и запуск

Требуется Python 3.11 или новее. Команды для macOS и Linux:

```bash
git clone https://github.com/fismay/iikuzn-misis-drm-tm.git
cd iikuzn-misis-drm-tm
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install -e ".[ranker]"   # extra только для обучаемого ранжировщика
python -m pytest tests -q
python -m app.run_pipeline --synthetic --output artifacts/demo
python -m streamlit run app/streamlit_app.py -- --artifact-dir artifacts/demo
```

Для Windows PowerShell команда активации: `.venv\Scripts\Activate.ps1`. После запуска Streamlit откройте адрес, который появится в терминале.

Проверка по официальному протоколу организаторов (книга и фид не входят в репозиторий — положите их в `data/raw/`):

```bash
curl -o data/raw/Mindbox.yml.gz https://store.softline.ru/feeds/Mindbox.yml.gz
python -m app.run_pipeline --workbook data/raw/source.xlsx --official \
  --feed data/raw/Mindbox.yml.gz --output artifacts/demo
```

Артефакты — `artifacts/demo/official/official_metrics.json` и `ranker.pkl`; Streamlit покажет таблицу, если артефакты есть. Без extra `ranker` работает эвристика (`--skip-ltr`).

Демонстрация использует **синтетические данные**: её метрики показывают работу кода и не являются результатами на клиентах. Реальные результаты по протоколу организаторов — в таблице выше и в артефактах.

## Данные и проверка

Загрузчик принимает отдельные CSV- или XLSX-файлы клиентов, товаров и транзакций с явным JSON-сопоставлением полей. Подробности — в [описании сопоставления](docs/data/input_mapping.md). Реальные выгрузки, локальные сопоставления и результаты с идентификаторами клиентов не следует добавлять в репозиторий.

Встроенный бэктест использует собственный временной протокол и отличается от протокола организаторов (например, Fill Rate там — доля заполненных позиций, а у организаторов — доля клиентов с хотя бы одной рекомендацией). При сравнении результатов необходимо явно указать выборку, период и определения метрик.

Каталог и вендорные признаки берутся из текущего снимка фида (может содержать информацию из будущего относительно даты отсечения); это объявлено в docs. Данные о ценах и показах отсутствуют, поэтому по ним нельзя измерить прирост выручки или доказать влияние рекомендаций на продажи. Проверка на истории не заменяет эксперимент в личном кабинете.

## Структура

- `src/reco_mvp/data/` — подготовка и проверка данных.
- `src/reco_mvp/recommender/` — модель рекомендаций и обучаемый ранжировщик.
- `src/reco_mvp/evaluation/` — проверка на истории: внутренний протокол и протокол организаторов.
- `src/reco_mvp/enrichment.py` — обогащение связями из фида каталога.
- `app/` — запуск сценария и интерфейс.
- `contracts/` — формат данных и программные интерфейсы.
- `docs/` — описание модели, протоколов и запуска.
- `tests/` — автоматические проверки, включая golden-сверку baseline организаторов.
