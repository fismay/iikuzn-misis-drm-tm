# Демонстрация до 3 минут, одним непрерывным фрагментом

1. Проблема: возврат клиента в кабинет — возможность предложить подходящее дополнение.
2. Данные: продажи и каталог; явно обозначить источник и ограничения.
3. Метод: связи покупок и резервная популярность по сегменту.
4. Показать клиента, три рекомендации, причины и связь с историей. Показать нового клиента.
5. Показать сравнение метрик и размер выборок. Синтетика подтверждает работу кода, а не рост продаж.
   На реальных данных — таблица официального протокола организаторов (Streamlit или
   `artifacts/demo/official/official_metrics.json`): baseline «популярность» 5.44% → эвристика 12.76% →
   ранжировщик 14.34% Precision@3 при Fill Rate 100% в группе A; группа B (один товар в истории) — 15.50%;
   отдельно показать долю попаданий-вариантов (~35–46% против 10.5% у baseline).
   Группа B не является группой холодного старта. Отдельно показать нового клиента,
   для которого рекомендации заполняются популярностью: Fill Rate не растёт
   относительно baseline популярности. Подчеркнуть: подбор только на внутренних окнах до отсечения; официальный период
   проверен один раз; B2C-подвыборки шумные; это наблюдение на истории, а не рост выручки.
6. Следующий этап: пилот в ЛК, журнал показов и онлайн-эксперимент.
