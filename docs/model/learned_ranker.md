# Обучаемый ранжировщик (LTR)

`reco_mvp.recommender.ltr` ранжирует кандидатов штатного рекомендателя
градиентным бустингом (`HistGradientBoostingClassifier`) по 37 признакам
доказательств: сила связей co-purchase (в корзине и между корзинами),
условные вероятности, популярность (общая, сегментная, свежая), продление
внутри `product_group`, вендор/категория из фида, похожие клиенты, профиль
клиента. Эвристика (`Recommender` с `BEST_CONFIG`) остаётся объясняющей
поверхностью: у неё берутся кандидаты, у неё же — причины для интерфейса.

## Протокол подбора (честность)

- Внутренние окна обучения: шесть окон `(train_end, test_start, test_end)` от
  25.01.2026 до 31.05.2026 (`INTERNAL_TRAIN_WINDOWS`), строго до официального
  отсечения 2026-08-31. Разметка каждого окна — покупки его собственного
  будущего среза; признаки — только из обучающих строк этого окна.
- Подбор эвристических параметров — на двух внутренних валидационных окнах
  (01.06–31.08 и 31.07–07.09.2026); гиперпараметры бустинга — по первому.
- Официальный тестовый период (с 07.09.2026) использован один раз для финальной
  сверки; по нему ничего не выбиралось.
- Детерминизм: `random_state=42`, однопоточный сбор гистограмм sklearn (threadpoolctl) и
  детерминированный порядок кандидатов/признаков; прогон `--official` воспроизводит
  таблицу бит-в-бит при тех же данных и версии scikit-learn.

Диагностика перед выбором подхода (внутреннее окно): около 69% промахов —
товары, которые были в кандидатах, но не попали в топ-3; то есть узкое место —
ранжирование, а не генерация кандидатов. Поэтому LTR ранжирует, а не генерирует.

## Что объявляется явно (утечки и допущения)

- `available_from` всех товаров из текущего снимка каталога выставлен датой до
  начала данных: товар считается доступным по текущему фиду. Организаторы
  разрешили текущие данные каталога с обязательным указанием; исторических
  снимков каталога, наличия и профилей клиентов в датасете нет.
- Вендор и категории — текущий снимок фида `Mindbox.yml.gz` (может содержать
  информацию из будущего относительно даты отсечения). Цены не используются.
  Сегмент (`client_group`) и отрасль — текущие справочники.
- Разметка обучается по тем же правилам, что и внутреннее «будущее»; в тестах
  периода не участвует.
- Совпадения в малых группах (B2C: 35/25 клиентов) шумные; итоговые метрики
  подаются с этим предупреждением.

## Ограничения

- Модель не ранжирует товары без истории покупок (холодные товары фида): таких
  кандидатов просто нет в пуле. Объяснения не обещают совместимость и экономику.
- Требуется scikit-learn: `pip install 'reco-mvp[ranker]'`. Без него пакет
  работает на эвристике; `LtrAgent` поднимает понятный `ImportError`.
- Проверка модели в проде — по артефакту `ranker.pkl` и метаданным
  (окна, строки, признаки, `feed_available`); загрузка модели с другим набором
  источников фида блокируется явной ошибкой.
- Продление, апсейл, денежный эффект и превосходство над baseline в проде не
  заявлены: сравнение с baseline — только на истории, в протоколе организаторов.
